# Вопросы

## 1. В чем разница между sync.Mutex и sync.RWMutex? Когда какой использовать?

Ответ:

При `sync.Mutex` в каждый момент времени только одна горутина может удерживать блокировку, 
независимо от того, читает она данные или изменяет их.

При `sync.RWMutex` блокировки разделяются и одновременно может быть несколько читателей.

`RWMutex` имеет смысл, когда чтений существенно больше, чем записей, и читатели не мешают друг другу – тогда они работают параллельно. 
Если записей много или критические секции короткие, `RWMutex` проигрывает по производительности, и быстрее обычный `Mutex`. 
В нашей задаче читают (`GetResult`, `GetResponsesCount`) заметно чаще, чем пишут, поэтому `RWMutex` подходит.

## 2. Что такое race condition и как его избежать в Go?

Ответ: Состояние гонки – это ситуация, когда несколько горутин обращаются к общим данным без синхронизации, и итог зависит от порядка выполнения, поведение недетерминировано.

Как избегать:
- передавать данные между горутинами через каналы
- защищать общие данные мьютексами или атомиками
- не менять общие структуры (например, `map`) из нескольких горутин без блокировки
- запускать тесты с `-race` и писать тесты, чтобы проверять гонки

## 3. Как правильно обрабатывать отмену контекста в горутинах?

Ответ: Передавать `ctx` в горутину и слушать `ctx.Done()` в `select` вместе с полезной работой:

```go
select {
case <-ctx.Done():
    return
case result := <-ch:
    // тут какая-то наша логика
}
```

## 4. В чем преимущества и недостатки использования каналов vs sync.WaitGroup для синхронизации горутин?

Ответ:
- `sync.WaitGroup` – простой счетчик завершения.
- Плюсы: минимальные накладные расходы, простой код, подходит для случая, когда надо запустить N горутин и ждать их завершения.
- Минусы: не передает данные, нет отмены, не возвращает ошибки и результаты.
  
- Каналы – передают данные и синхронизируют через коммуникацию. 
- Плюсы: удобно передавать результаты, работать с `select`, строить пайплайны, ограничивать параллелизм. 
- Минусы: больше кода, выше накладные расходы, легко получить утечку горутин, заблокироваться, если забыть закрыть канал или читателя.

Поэтому, удобно комбинировать их.

## 5. Зачем нужен флаг -race в Go?

Ответ: `-race` включает детектор гонок данных. 
Он находит обращения к одной памяти из разных горутин без синхронизации. 
Это критично для конкурентного кода, потому что такие баги недетерминированы и могут пропускаться при обычном запуске.
