# Вопросы

## 1. Чем можно было заменить нашу кастомную ошибку `AdditionalMessageError`, чтобы быстрее и проще добавлять контекста в сообщение ошибки?

Ответ: Можно было использовать просто `fmt.Errorf`:

```go
return fmt.Errorf("I can write here everything I want: %w", err)
```

Это проще и быстрее, не нужно писать свою структуру, конструктор и методы.

Кастомная ошибка оправдана, если кроме текста нам нужно хранить и использовать какую-то дополнительную информацию.

## 2. Что произойдет, если в методе `Error()` структуры `AdditionalMessageError` мы забудем обработать случай, когда `err == nil`?

Ответ: Получим панику `invalid memory address or nil pointer dereference`, потому что попытаемся обратиться к методу объекта, который не существует в памяти.

## 3. В чем разница между `errors.Is()` и `errors.As()`? Когда какой метод использовать?

Ответ:
- `errors.Is(err, target)` — проверяет, есть ли в цепочке ошибка, равная `target`. Для проверки наличия конкретной ошибки.
- `errors.As(err, &target)` — находит в цепочке первую ошибку, которую можно присвоить к типу `target`, и кладет ее значение в `target`. Для извлечения типизированной ошибки и использования её методов.

P.S. Goland предложил использовать `errors.AsType[*target](err)` вместо `errors.As()`.


## 4. Почему в handler'е мы проверяем наличие ошибок в error chain, а не сравниваем типы напрямую?

Ответ: Потому что ошибка может быть обёрнута в другие ошибки, и прямое сравнение типов не найдёт исходную ошибку внутри цепочки.
